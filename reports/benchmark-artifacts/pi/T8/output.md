# 熔断纪律：连续同形态失败观察与停线机制

> **交付定位**：一份可直接落地的治理规范 + 配置契约 + 运行手册（Runbook）。
> **核心命题**：把"同一个错误反复出现"从**噪声**升级为**信号**——一旦识别到连续同形态失败，系统必须在造成更大范围损害前**自动停线**，而不是继续重试、继续放大。
> **不依赖任何预置数据文件**，规则、阈值、状态机均为通用业务基线，可按组织实际替换。

---

## 0. 一页话（Executive Summary）

| 项目 | 结论 |
|---|---|
| 要解决的问题 | 同一根因导致的失败被逐条当成独立事件处理，重试掩盖真实故障，最终演变成批量事故 |
| 核心机制 | **同形态失败指纹 + 连续计数 + 自动停线（fail-safe） + 审批后复位（fail-secure）** |
| 关键设计取向 | 停线**自动、无需审批**；恢复**必须审批、必须凭证据** |
| 默认阈值 | 严格连续 **3 次**同形态失败 → 进入 OPEN 停线；滑动窗 **5 分钟 5 次** → 提前预警 |
| 停线粒度 | 执行体级 → 任务级 → 流水线级 → 租户/区域级，逐级升级 |
| 不可谈判项 | 停线动作不可被业务方"一键跳过"；跳线必须留痕并计入事故复盘 |
| 必备留痕 | 触发时间、形态指纹、样本、状态迁移、停线动作、审批人、复位证据、探针结果 |

## 1. 目的与适用范围

### 1.1 目的
1. **抑制放大**：阻断"重试风暴 / 雪崩 / 脏数据批量写入"这类由重复失败驱动的二次损害。
2. **提升信噪**：把"连续同形态失败"作为高置信故障信号，优先于人工报警受理。
3. **规范复位**：避免故障抖动期的反复上下线（flapping），恢复必须是"受控、可证、可审"的动作。
4. **可复盘**：每次停线与复位都生成结构化事件，供根因分析与阈值调优。

### 1.2 适用范围
- 数据/任务流水线（ETL、批处理、对账、报表生成）
- Agent / 工作台工具调用链（工具调用失败、解析失败、外部 API 失败）
- 对外接口与集成（第三方回调、Webhook 投递、消息队列消费）
- 发布与变更流程（灰度发布内的连续同形态异常）

### 1.3 不适用（明确排除，防误用）
- 单次、独立、形态互不相同的失败（走普通告警，不熔断）
- 已由上游显式声明的计划内维护窗口（走维护模式，不重复停线）
- 若"停线"代价高于故障代价的极端场景（需在配置中显式标注并单独审批豁免，见 §10）

## 2. 术语与判定基线

| 术语 | 定义 |
|---|---|
| **失败事件 Failure Event** | 一次操作以失败/超时/异常态结束，并带有可用结构信息 |
| **失败形态 Failure Shape** | 对失败的结构化归类，如 `阶段=写入`、`类型=约束冲突`、`错误码=23505`、`节点=order-sync` |
| **形态指纹 Fingerprint** | 对形态字段做**归一化**（剥离易变字段）后计算的稳定哈希，同形即同指纹 |
| **连续同形态失败 CSSF** | 在观测窗内，**不被打断**地重复出现同一指纹的失败序列 |
| **观察窗 Window** | 计数所覆盖的时间/事件范围，默认滑动 5 分钟 或 最近 N 个事件 |
| **熔断 Breaker Trip** | 达到阈值，状态由 CLOSED/OBSERVING 迁入 OPEN |
| **停线 Stop-the-Line** | 熔断后实际执行的阻断动作；按严重度分级（见 §6） |
| **复位 Reset** | 经审批与探针验证后，由 OPEN → HALF-OPEN → CLOSED |

### 2.1 形态指纹的构造规则（关键，决定误报率）
指纹 = `hash( 阶段 | 错误类型 | 错误码/模板化文案 | 受影响对象类别 | 调用链节点 | 依赖目标 )`

必须做的归一化：
- **剥离**：时间戳、自增 ID、UUID、请求 ID、随机数、分片号、重试次数、耗时
- **模板化**：把 `用户 12345 不存在` 归一为 `用户 {id} 不存在`
- **保留**：错误语义、阶段位置、受影响资源**类别**（不是具体实例）

> 纪律：**指纹算法必须在本地/边界内计算**，只上报指纹与形态标签，不上报原始敏感文本（见 §8）。

## 3. 触发模型

### 3.1 双通道判定（避免"偶发抖动即熔断"）

| 通道 | 规则 | 默认值 | 作用 |
|---|---|---|---|
| **严格连续通道** | 同一指纹计数 ≥ N，中间无其它形态事件打断 | N = 3 | 主熔断条件，置信度高 |
| **滑动窗通道** | 窗口内同一指纹出现 ≥ K 次 | 5 分钟 / K = 5 | 提前预警 / 加速熔断 |
| **占比通道**（可选） | 窗口内该指纹占比 ≥ P 且总量 ≥ M | P = 60%，M = 10 | 应对高流量下的快速恶化 |

- 命中**任一**通道即可触发告警；严格连续通道命中即触发**停线**。
- 设置 **冷却期 Cooldown**（默认 60 秒）：冷却期内不重复触发同一停线动作，防止动作风暴。
- "连续"的口径：**同指纹失败递增计数**；**任何一个非该指纹的失败、或针对该路径的成功**都将计数清零（可在配置中选择是否被"成功"清零）。

### 3.2 阈值参考矩阵

| 影响面 | 严格连续 N | 动作等级 | 说明 |
|---|---|---|---|
| 单执行体（worker/实例） | 3 | L1 隔离 | 快速摘除坏节点 |
| 单任务/单租户 | 3 | L2 冻结写 | 保护下游数据 |
| 共享流水线 | 2–3 | L3 停线 | 阻断上游放大器 |
| 跨租户核心链路 | 2 | L4 全量熔断 | 最高等级，最保守 |

> 阈值需按"失败代价 vs 停线代价"标定，并在事故复盘后回写。**任何阈值调整必须走变更记录**。

## 4. 状态机（Circuit Breaker）

```
         ┌─────────────── 复位审批通过 + 探针达标 ───────────────┐
         │                                                      │
         ▼                                                      │
   ┌──────────┐  同形态失败计数 ≥ N   ┌────────┐  冻结/停线执行   ┌───────────┐
   │ CLOSED    │ ─────────────────────▶ │ OPEN   │ ───────────────▶ │ 停线生效   │
   │ 正常放行  │                        │ 已熔断 │                   │ (阻断中)  │
   └──────────┘ ◀───────────┐          └────────┘                   └───────────┘
         ▲                   │               │ 冷却期结束
         │                   │               ▼
         │            探测成功(≥连续S次)  ┌───────────────┐
         └──────────────────────────────│  HALF-OPEN     │
                                        │ 小流量探针     │
                                        └───────────────┘
                                               │ 探测失败
                                               ▼
                                         回到 OPEN（并延长冷却/升级等级）
```

| 状态 | 行为 | 允许的写操作 |
|---|---|---|
| CLOSED | 正常放行，后台计数 | ✅ |
| OBSERVING | 放行但**降速**、标记高风险、开启样本采集 | ✅（限速） |
| OPEN | 执行停线动作 | ❌（按 §6 等级） |
| HALF-OPEN | 仅放行探针流量（默认 1% 或固定 QPS） | ⚠️ 仅探针 |

**关键纪律**：HALF-OPEN 中只要探针再次出现**同形态失败**，立即回到 OPEN，且**不可让步**（不因"已经投入很多"而放行全量）。

## 5. 注入点与采集（观测管线）

> 本任务标题中的"注入"，落地为**在关键路径上埋入失败观测探针**，使连续同形态失败可被识别。

### 5.1 注入位置（最少覆盖）
1. **执行入口**：任务/调用开始（用于成对计算成功率）
2. **执行出口**：失败发生点（产出原始失败事件）
3. **依赖边界**：外部 API / DB / MQ 的返回处
4. **写操作前哨**：所有写库/写下游动作之前（用于实现 L2"冻结写"）
5. **重试器内部**：拦截"重试掩盖故障"（重试也要计入形态计数）

### 5.2 观测管线六步
```
采集 → 归一化(剥离易变字段) → 指纹计算 → 计数与窗口维护 → 阈值判定 → 动作派发
```
- **计数存储**：按（指纹 × 作用域）维护计数器与窗口；分布式场景使用原子计数或有界队列。
- **幂等要求**：重复上报不得造成重复计数（用 事件 ID 去重）。
- **背压保护**：观测管线自身失败时**不得阻断业务**，但需自监控并告警（避免"监控拖垮生产"）。

### 5.3 采样与取证
- 熔断触发时，**冻结**最近 W 条原始失败样本（默认 20 条）作为取证材料；
- 样本在**入库/上报前完成脱敏**（§8）；原始样本保留于受限存储。

## 6. 分级停线动作（Action Ladder）

| 等级 | 名称 | 动作 | 默认触发 | 需审批 |
|---|---|---|---|---|
| **L0** | 观察 | 打标、加速采样、发预警 | 滑动窗命中 | 否 |
| **L1** | 隔离 | 摘除故障执行体/实例、停止向其派发 | 单执行体连续 3 | 否 |
| **L2** | 冻结写 | 切只读降级、暂停写库/写下游、停止投递 | 单任务连续 3 | 否 |
| **L3** | 停线 | 暂停整条流水线/消费组，保全队列 | 共享链路连续 2–3 | 否（自动） |
| **L4** | 全量熔断 | 跨租户/跨区域阻断，切降级/静态兜底 | 核心链路连续 2 | 否（自动）+ 立即通知 |

**纪律要点**
- **自动向上兼容，不自动向下**：一旦升到 L3，不得自动降回 L2——降级必须人来判。
- **停线是 fail-safe**：宁停勿炸；停线本身**无需审批**（否则纪律形同虚设）。
- **停线必须可逆**：所有动作都要预置对应的**解除动作**与**回滚脚本**，且经过演练。
- **停线不得丢数据**：停线时冻结输入队列、保留偏移量（offset）/位点，禁止"清队列重启"。

## 7. 恢复、复位与审批

### 7.1 复位四关（全部通过才可 CLOSED）
1. **根因关**：已定位根因（或已确认外部依赖恢复），并有证据/工单
2. **审批关**：**双人复核**（Two-Person Rule）——值班负责人 + 领域负责人（见 §7.2）
3. **探针关**：HALF-OPEN 小流量探针连续成功 ≥ S 次（默认 S = 10）且无同形态失败
4. **观测关**：复位后保持**增强监控** ≥ 30 分钟，期间同形态失败再次出现则立即回 OPEN

### 7.2 审批矩阵（明确纳入审批流程）

| 动作 | 发起方 | 审批方 | 审批形式 | 时限 |
|---|---|---|---|---|
| 触发 L1–L4 停线 | 系统（自动） | 无需审批（事后知会） | 自动留痕 | 即时 |
| 解除 L1/L2 | 值班工程师 | 值班负责人 | 单签 | 15 分钟内 |
| 解除 L3 | 值班工程师 | **值班负责人 + 领域负责人** | **双签** | 30 分钟内 |
| 解除 L4 | 事故指挥 | **双签 + 变更记录** | **双签 + 事后复盘** | 立即开事故通道 |
| 跳过/豁免熔断（临时） | 业务方 | **双签 + 风险接受书** | 双签 | 必须先登记工单 |
| 调整阈值 | 平台/SRE | 变更评审 | CR 审批 | 常规变更窗口 |

> **审批留痕必含字段**：审批人身份、时间、依据的形态指纹与样本编号、探针结果、风险接受范围、有效期（临时豁免必须设**到期自动失效**）。

### 7.3 复位反模式（禁止）
- ❌ 直接改阈值把熔断"绕过"
- ❌ 重启进程让计数器清零（计数器须持久化/外部化）
- ❌ 未经探针直接全量放行
- ❌ 同一根因未修复就"再试一次"

## 8. 脱敏与合规（明确要求）

> 失败样本天然携带业务数据，**必须先脱敏再流转**。

| 类别 | 处理方式 |
|---|---|
| 个人身份信息（姓名、手机号、证件、地址） | 掩码/替换为占位符（如 `{PII:PHONE}`），**不可逆** |
| 账号、Token、密钥、Cookie、Authorization 头 | **直接删除**，仅保留"存在/不存在"标记 |
| 业务敏感字段（金额、订单号、客户编号） | 保留**格式与类别**，值做哈希或泛化（如 `金额={RANGE:1k-10k}`） |
| 原始报文 / 堆栈中的路径与参数 | 模板化为 `{id}`、`{path}` |
| 指纹计算 | **在边界内本地计算**，仅上报哈希与形态标签 |
| 原始样本存储 | 受限目录/加密、最小权限、**保留期默认 30 天**后自动清除 |
| 跨环境流转 | 生产样本**不得**直传开发/测试环境；需经脱敏管道 |

**合规声明**：本机制涉及失败样本采集与留存，需在组织隐私/安全政策下登记；若涉及受监管数据（如金融/医疗），采集范围与保留期须经合规会签，并在配置中显式声明数据分级。

## 9. 指标、看板与告警

| 指标 | 定义 | 目标 |
|---|---|---|
| MTTD（平均发现时间） | 首次同形态失败 → 熔断触发 | < 1 分钟 |
| MTTR（平均恢复时间） | 熔断 → CLOSED | 分层目标（L1<15m，L3<30m） |
| **误熔断率** | 停线后判定为"非真实故障"的比例 | < 5% |
| **漏熔断率** | 事后复盘发现本应熔断但未熔断 | ≈ 0（一票否决项） |
| Flapping 率 | 同链路 24h 内反复 OPEN/CLOSED | < 2 次/天 |
| 样本脱敏合规率 | 上报样本中脱敏合格比例 | 100% |

**告警纪律**：告警必须**可执行**（带停线等级、形态指纹、一键跳转 Runbook）；不可执行告警视为噪声，需在复盘中降噪。

## 10. 配置契约（示例 YAML）

```yaml
breaker:
  version: 1
  scope: "pipeline/order-sync"          # 作用域：执行体 / 任务 / 流水线 / 租户
  fingerprint:
    fields: [stage, error_type, error_code, object_class, node, dependency]
    strip:  [ts, request_id, uuid, retry_count, duration_ms, shard]
    template: true                       # 值模板化（user {id} not found）
  rules:
    strict_consecutive:
      enabled: true
      threshold: 3                       # 连续同形态失败 ≥ 3
      reset_on_success: true             # 任一成功清零
    sliding_window:
      enabled: true
      window_seconds: 300
      threshold: 5
    ratio:
      enabled: false
      min_total: 10
      ratio: 0.6
  cooldown_seconds: 60
  actions:
    L1: { action: "quarantine_instance", auto: true,  approval: none }
    L2: { action: "freeze_writes",       auto: true,  approval: none }
    L3: { action: "pause_pipeline",      auto: true,  approval: none, notify: [oncall, owner] }
    L4: { action: "global_block",        auto: true,  approval: none, notify: [incident_channel] }
  not_pausable: true                     # 停线动作不可被业务侧跳过
  evidence:
    freeze_samples: 20
    desensitize: true                    # 强制脱敏

      traffic_ratio: 0.01

    approvals:
      L1: ["oncall_lead"]
      L2: ["oncall_lead"]
      L3: ["oncall_lead", "domain_owner"]   # 双签
      L4: ["oncall_lead", "domain_owner", "incident_commander"]
    enhanced_monitor_minutes: 30
  exceptions:
    allow_temporary_waiver: true
    waiver_requires: ["two_person", "risk_ack", "ticket", "expiry"]  # 必须含到期时间
```

## 11. 参考实现（伪代码）

```python
def on_failure(event, cfg):
    ev = desensitize(normalize(event))         # 归一化 + 脱敏（先脱敏后落库）
    fp = fingerprint(ev, cfg.fingerprint)      # 形态指纹

    key = (cfg.scope, fp)
    state = store.get_state(key)               # CLOSED / OBSERVING / OPEN / HALF_OPEN
    if state == OPEN:
        return pause_action(cfg)               # 已停线，不再重复动作

    n = counter.increment(key, ev)             # 幂等计数
    if hit_sliding_window(key) or hit_ratio(key):
        alert(level="L0", fp=fp)

    if n >= cfg.rules.strict_consecutive.threshold:
        freeze_evidence(key, cfg.evidence)     # 冻结样本（已脱敏）
        action = escalate(cfg, scope=cfg.scope, fp=fp)   # L1→L4 取最高适用
        store.set_state(key, OPEN)
        execute(action)                        # 自动停线，无需审批
        audit("TRIP", fp=fp, action=action, count=n, samples=frozen_ref)
        return

def on_success(event):
    # 打断连续序列（若配置 reset_on_success）
    key = (cfg.scope, fingerprint(normalize(event), cfg.fingerprint))
    counter.reset(key)

def try_reset(key, evidence, approvers):
    if not two_person_approved(approvers, level=key.level):
        raise Blocked("需要双人审批")
    store.set_state(key, HALF_OPEN)
    result = run_probe(key, cfg.recovery.probe)
    if result.consecutive_success >= cfg.recovery.probe.min_consecutive_success:
        store.set_state(key, "CLOSED")
        audit("RESET", approvers=approvers, probe=result, evidence=evidence)
        schedule_enhanced_monitor(key, cfg.recovery.enhanced_monitor_minutes)
    else:
        store.set_state(key, OPEN)             # 探针失败 → 回 OPEN，不可让步
        audit("RESET_FAILED", probe=result)
```

## 12. 验收标准与测试用例

### 12.1 验收清单
- [ ] 同形态失败计数**跨进程重启不丢失**（计数器外部化）
- [ ] 剥离开时间戳/ID 后，同形失败**确实聚合**为同一指纹
- [ ] 连续 N 次同形态失败在 1 分钟内触发停线
- [ ] 停线动作生效（写入被阻断 / 队列保留位点 / 无数据丢失）
- [ ] 恢复必须经过双签 + 探针，缺一不可
- [ ] 上报/存储样本 100% 脱敏，原始样本受限且按期清除
- [ ] 阈值调整留变更记录；豁免有到期自动失效
- [ ] 观测管线自身故障不阻断业务，但会告警

### 12.2 必测用例（建议纳入回归）
| # | 场景 | 期望 |
|---|---|---|
| T1 | 3 次同指纹失败（中间夹 1 次成功） | 计数清零，不熔断（严格连续） |
| T2 | 3 次同指纹失败（中间夹**不同**指纹失败） | 主指纹计数清零，不误熔断 |
| T3 | 5 分钟内同指纹 5 次（非连续） | 命中滑动窗，至少 L0 预警 |
| T4 | 熔断后人为重启进程 | 仍为 OPEN，不得复活写操作 |
| T5 | HALF-OPEN 探针再遇同形态失败 | 立即回 OPEN |
| T6 | 双人审批缺失时尝试复位 | 被阻断 |
| T7 | 触发熔断冻结样本 | 样本已脱敏，PII/Token 不可回溯 |
| T8 | 停线期间上游持续投递 | 队列位点保留，复位后可续跑，无重复/丢失 |

## 13. Runbook（值班纪律）与 RACI

### 13.1 值班处置顺序（收到熔断告警）
1. **确认范围**：看停线等级、作用域、指纹、影响面（多少租户/多少下游）
2. **保全现场**：确认样本已冻结、位点已保留，**禁止清队列重启**
3. **止损优先**：若自动动作未完全止血，手工升级到高一等级
4. **定位根因**：结合形态指纹与样本，判断是自身缺陷 / 依赖故障 / 配置错误 / 数据异常
5. **修复 + 探针**：修复后走 HALF-OPEN，达标才全量
6. **复位审批**：按 §7.2 取签；L4 同时开事故复盘
7. **复盘回写**：阈值、指纹字段、Runbook 是否需要调整

### 13.2 RACI

| 环节 | 平台/SRE | 值班负责人 | 领域负责人 | 业务方 | 合规/安全 |
|---|---|---|---|---|---|
| 定义阈值与指纹 | **R/A** | C | C | C | C |
| 自动触发停线 | **R/A** | I | I | I | — |
| 处置与根因 | R | **A** | R | C | C |
| L3/L4 复位审批 | C | **R** | **A** | I | C |
| 临时豁免/阈值调整 | C | A | R | **R** | C（涉敏） |
| 脱敏合规 | R | I | C | I | **A** |
| 事故复盘 | R | R | **A** | C | C |

（R=负责、A=最终问责、C=被咨询、I=被告知）

## 14. 附：常见反模式清单（落地时逐条对照）

1. 把成功也计入"连续"——造成真实故障被稀释，漏熔断。
2. 指纹字段粒度过细（含 ID/时间戳）——永不聚合，永不熔断。
3. 重试器在熔断之外——重试掩盖故障，风险放大。
4. 停线需要审批——停产批不下来，纪律失效。
5. 恢复无需审批——未经修复反复上线，flapping。
6. 计数器存内存——重启即清零，形同虚设。
7. 清队列重启——数据丢失且毁灭证据。
8. 豁免无到期——永久后门。
9. 样本不脱敏——泄漏 PII/密钥，引入合规事故。
10. 告警不可执行——噪声掩盖信号。

**审批说明**：本机制涉及**自动停线（免审批）**与**恢复/豁免/阈值调整（需审批）**两类动作，审批矩阵见 §7.2；L3/L4 恢复与临时豁免强制**双人签核**并绑定有效期。
**脱敏说明**：所有失败样本、指数字段、上报载荷在离开信任边界前完成脱敏（§8），原始样本受限存储并按期清除；指纹在本地计算，仅上报哈希与形态标签。

**待你确认的三项（影响落地参数）**：① 首个接入的作用域（建议从"共享流水线"起步）；② 默认严格连续阈值 N（建议 3）与滑动窗（建议 5 分钟/5 次）；③ 是否已具备双人审批通道与样本受限存储——两项缺一时，需先补基础设施再开启 L3/L4 自动停线。
