## 交付正文（摘要 + 结构）

**《企业智能工作台（AI Agent）30 天落地实施计划 v1.0（草案）》**

**0. 合规声明**：文中审批矩阵、数据分级、脱敏规则均为**建议模板**，须经信息安全/法务/内控确认裁剪；示例字段名均为占位符，非真实数据资产清单；涉及 PII、生产数据、对发布的动作一律**先批后做**。

**1–2. 目标与边界**
- 北极星：30 天交付 **1 个可用 Agent 场景 + 1 套可复制方法论 + 1 套安全护栏**
- 6 条可验收成功标准（UAT ≥90%、试用 ≥30 人 NPS ≥30、耗时下降 ≥30%、泄露/越权事件 = 0、方法论可复制、Gate-3 有明确结论）
- 明确 Out of Scope：资金支付与合同签署类**自动化执行**、个人信息出域、全量系统打通

**3. 四阶段路线图**

```
D1────D7 阶段一 诊断与对齐  → Gate-0 锁目标/范围/审批链
D8────D15 阶段二 试点搭建MVP → Gate-1 可演示、关键用例全过
D16───D23 阶段三 集成+治理   → Gate-2 可集成、可审计（高危安全项不闭环不得进入下一阶段）
D24───D30 阶段四 评估+固化   → Gate-3 推广/调整/终止决议
```

**4. 30 天日历级任务表**：逐日列出任务、优先级（P0/P1/P2）、责任角色、产出物、依赖；🔒 标记所有涉及**审批或脱敏**的节点（D3 数据分级与权限申请、D16 生产接入审批、D22 安全合规终审、D29 权限回收）。

**5–7. 治理**：RACI 矩阵（含"四类事项 A 必须为职能负责人本人、PM 不得代批"）、4 个 Gate 的通过条件与 60 分钟固定议程、三层指标体系（北极星 = WAU × 人均任务数 × 单任务节省工时，含 3 项护栏指标必须为 0）。

**8. 数据安全、脱敏与审批（核心章）**
- **分级**：L1 公开 / L2 内部 / L3 敏感（须脱敏）/ L4 核心（默认禁入 Agent 上下文），Agent 默认可访问上限为 L2
- **脱敏矩阵**：姓名、手机号、身份证、账号、地址、客户名、金额、**自由文本**、日志共 10 类字段的处理方式与是否可逆
- 五项实施要求：**双层防护（源头+出口）、不可逆优先、自由文本双重清洗、防聚合推断、测试环境禁用真实数据**
- **审批矩阵**：数据类 6 项 + 系统变更类 4 项，逐项列审批链与 SLA；执行规则含**留痕、超时升级、未回应视为不通过（不默许）、禁止自批、季度权限复核**
- **审计**：6 类记录字段、≥6 个月留存、任意输出可回溯到"数据来源+版本+规则"、4 类实时告警
- **例外路径**：审批未完成时用脱敏样例先行开发；发现疑似泄露 → 立即停止能力、1 小时内上报、禁止自行处置

**9–15**：12 项风险登记册（4 项红色）、约 147 人日资源估算、沟通机制、变更管理与**三条变更红线**（降低安全标准/绕开审批/扩大数据访问范围不批）、19 项交付物清单、5 个可直接使用的模板（周报、Gate 清单、脱敏申请单、上线审批单、待确认事项表）。

## 关于 DOCX

`.docx` 是 ZIP 二进制容器，无法用文本写入方式直接产出，因此本包交付**正文 + 一键转换脚本**：

```bash
pip install python-docx && cd deliverables && python build_docx.py
```

生成的 docx 已内置封面、目录域（Word 中 Ctrl+A→F9 刷新页码）、页脚页码、表头跨页重复、中文字体与 4 级标题。若已装 pandoc 可用 `python build_docx.py --pandoc` 兜底。
