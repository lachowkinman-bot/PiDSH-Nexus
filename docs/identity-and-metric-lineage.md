# PiDSH Nexus 跨域身份、指标与证据血缘

## 目标

13 个业务域可以独立运行，但战略总看板必须能把经营结果追溯到同一套对象、工作流和数据版本。跨域只传不可还原的匿名键和聚合证据，不复制个人敏感信息。

## 匿名主键

| 键 | 用途 | 约束 |
|---|---|---|
| `person_key` | 员工、候选人、面试官、绩效对象的跨域匿名关联 | 不可由姓名/身份证/手机号直接推导；各域展示掩码仍可使用本地格式 |
| `position_key` | 岗位、编制、招聘、培训、薪酬带宽关联 | 岗位名称可变化，键不复用 |
| `customer_key` | 客户、商机、合同、收入、回款关联 | 不含客户实名或联系方式 |
| `contract_key` | 合同、报价条款、收入确认、回款关联 | 一条合同可有多个版本，版本必须单独留痕 |
| `initiative_key` | 战略举措与具体项目关联 | 可追溯到 Objective/KR |
| `trace_id` | 跨域副作用和审计事件关联 | 一次工作流运行内稳定，不跨实例复用 |

原始身份映射表必须位于受控命名空间，不进交付物、不进公网模型、不进记忆层。当前 13 域种子数据中的不同掩码格式可以在 UI 显示层保留，但跨域计算前必须解析为 `person_key`；解析失败不得猜测或模糊匹配。

## 工作流证据链

每条工作流实例记录：

1. `workflow_id`、`domain`、`instance_id`。
2. 输入来源、输入数据版本和文件哈希。
3. LLM 任务的 prompt version、模型、输出结构、证据引用和置信度。
4. 规则校验结果、质量评分和人工审批记录。
5. 产物文件、manifest、文件大小、SHA-256 和备份 ID。
6. 成效指标、贡献 KR、复核时间和下一周期行动。

审计账本采用 append-only JSONL；当前状态快照采用原子重写。任何重跑都新建 revision 或新实例，不覆盖历史审批和产物。

## 战略指标口径

战略总看板的每个数字包含：

- `metric_id`、显示名称、单位、基线和目标。
- `source_domain`、源表/源字段或工作流聚合定义。
- `actual`、`forecast`、`data_version`、`confidence`。
- `contribution`（该指标对 KR 的权重或映射）。
- `evidence_refs`（可点击回到实例、源行或产物）。

禁止：

- 手工录入没有来源的总数并直接进入战略看板。
- 将不同口径的收入、订单、预算、福利成本直接相加。
- 将招聘投递转化率当作入职人数目标，或将阶段人数混为累计人数。
- 把“未到 90 天”当作留存成功或失败。

## 变更流程

指标、匿名键或跨域关联规则变更时：

1. 修改 `manifests/strategy-model.json` 或对应域模型。
2. 运行 `node scripts/gen-domain-model.mjs --check`。
3. 运行 `node scripts/verify-workflow-platform.mjs`。
4. 通过后在 `reports/` 保留数据版本和测试证据，再更新 runtime build-id。
