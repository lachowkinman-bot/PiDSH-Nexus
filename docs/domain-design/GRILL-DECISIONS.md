# 13 域设计盘问记录

本轮按 `grill-me → grilling → domain-modeling` 方法，对“模块 → 事项 → 工作流 → 环节 → 数据/文档”的每个分支逐项盘问。以下不是建议，而是本轮及后续实现必须遵守的决策。

| # | 盘问 | 结论 | 被拒绝的替代方案 |
|---|---|---|---|
| 1 | 领域顶层真源是工作流还是工作模块？ | 以“域 → 模块 → 事项 → 工作流”为顶层语义，工作流仍是执行真源 | 只按 78 条工作流平铺；仅在 UI 中临时分组 |
| 2 | 一个域需要多少模块？ | 每域 3 个责任模块，模块数和事项数可随业务变化，但必须覆盖全部工作流 | 固定每域 6 个同构模块；按技术层而非业务责任分组 |
| 3 | 一个工作事项能绑定多条工作流吗？ | 可以，但必须指定唯一主工作流；当前 1 事项 = 1 工作流，避免责任模糊 | 一个事项无主流程；同一流程被多个事项重复认领 |
| 4 | 多步骤业务如何表达？ | 作为同一工作流内的阶段，不为每个步骤新建顶层工作流 | 把每个步骤都升级为工作流，造成 200+ 条难治理流程 |
| 5 | 每个环节的最小标准是什么？ | 输入、输出、规则/证据、门禁、失败处理、基准来源至少六项 | 只写“执行分析”“提交审批”等动作描述 |
| 6 | 输入怎么定义？ | JSON Schema 定义形状，TypeDict 定义字段语义，源 CSV/用户上传提供物理来源 | 用自由文本提示词充当输入契约 |
| 7 | LLM 输出怎么验收？ | 强制 JSON Schema、证据引用、confidence、redaction、模型与 prompt version；失败进入 blocked_model | 直接接受自然语言；无证据自动生成终态 |
| 8 | 人工审批在哪里？ | 只有需要对外、生效、处分、录用、付款、用印等动作才设置人工审批；双审批必须不同角色和操作者 | 所有流程一律人工审批；高风险动作免除审批 |
| 9 | 数据隐私边界如何跨域复用？ | 统一用匿名键与脱敏字段；EAP、薪酬、健康、招聘 PII 采用更严格域策略 | 各域自行决定 PII 口径；跨域复制个体原值 |
| 10 | 交付物如何证明完整？ | 每个正式交付包含 JSON、Markdown、7 种格式包、manifest、哈希和审计链 | 只给一个可下载文件；截图充当交付证据 |
| 11 | 战略结果如何回流？ | 每次 outcome 阶段写 metric snapshot，并关联 KR、域北极星、实例和数据版本 | 手工汇总战略数字；各域只出无来源 KPI |
| 12 | 新增或调整事项怎么做？ | 修改模块映射后运行 `design:build` 和 `design:verify`，覆盖率不是 78/78 则失败 | 直接改 UI 或单独写文档，不更新契约 |
| 13 | 每个阶段需要独立契约吗？ | 需要。每个阶段分别定义输入/输出 Schema、进入条件、证据、门禁、超时、重试和幂等键 | 只给整条工作流一份输入/输出 Schema |
| 14 | 行业阈值能否直接当验收线？ | 不能。阈值标记为草稿，必须由业务负责人确认并形成版本化策略后才生效；硬不变量独立于阈值 | 把示例数字写成永久硬编码规则 |
| 15 | 跨域数据如何关联？ | 只用 `person_key`、`position_key`、`customer_key`、`contract_key`、`initiative_key`、`trace_id` 等匿名键，通过 outbox 事件传递 | 复制原始姓名、手机号、身份证号或客户联系方式 |
| 16 | 人工审批如何证明操作者？ | 本地操作者注册表 + 角色授权 + HMAC 签名；签名绑定实例 revision、数据版本、草稿哈希、决定和时间 | 自由填写姓名/工号；仅检查两个字符串不同 |
| 17 | 每个工作流验收多少路径？ | 正常、校验驳回、审批驳回、双审批缺失/同人、模型失败恢复、敏感外发阻断、重启续跑，共 7 类 | 只跑正常路径；用单条样例代表全部工作流 |
| 18 | 插件和三方 provider 如何判定可用？ | 本地能力必须通过；“已安装”不等于“可用”；有配置真联调，无配置明确阻塞且零假成功 | 用启动日志或面板截图代替功能验收 |

## 关键边界

- `manifests/domain-work-design/**` 是模块与事项真源。
- `manifests/workflow-contracts/**` 是输入/输出 JSON Schema 真源。
- `manifests/typedict/**` 与 `templates/Type-Dict/field-type-dict.csv` 是字段语义真源。
- `manifests/benchmark-sources.json` 是外部标杆引用真源。
- 生成的 `docs/domain-work-design/<domain>.md` 是给人阅读的投影，不得反向手工修改。
