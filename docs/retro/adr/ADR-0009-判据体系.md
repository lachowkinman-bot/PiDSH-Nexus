# ADR-0009 · 判据体系：机械 DoD + 14 条语义禁令 + 模型级引擎判据

- **状态**：已采纳（as-built）｜**决策日**：2026-09-27 18:11 → 09-29 14:02 升级｜**模块**：M10/M11
- **证据**：`015` §14.6 / §15.2（L960-962、L978）、L968；`docs/delivery-announcement-checklist.md` B 项；`reports/u18-engine-integration.md`；`reports/credential-unblock-3.0.md` §36-51

## 背景
1.0/2.0 两次失败的**共同根因**（复盘九条中的最根性一条）：**把"门禁绿灯"当成"用户要求满足"**，从未回头问"这些门禁加起来等不等于用户要的东西"。其技术表现是**语义替换**——用便宜可得的东西替换掉真正要验的东西。

## 决策
1. **所有门禁给机械 DoD**（v2.1 的教训："新门禁无机械判据 → 判据被执行者自定自判"）。
2. **14 条语义禁令**（出现即 V1 一票否决）：
   `lint 通过=场景装载`｜`装载行=插件可用`｜`tarball 哈希正确=已安装`｜`HTTP 状态=工作台可达`｜`md 报告存在=UI 呈现`｜`维度覆盖表=质量对标`｜`文件计数=能力可用`｜`frontmatter 读取=技能装载`｜`路由存在=操作接通`｜`页面渲染=界面交付`｜`npm audit 空依赖=安全检查`｜`NOT_RUN 登记=合规交付`｜`探测代码存在=探测结果可信`｜`本地 JS 执行=引擎整合`。
3. **引擎判据升级为模型级**：`stopReason=stop` 且 `usage.totalTokens>0` 且正文非空——**不得用进程退出码**。
4. **门禁以"用户原始要求逐字枚举"为优先**："不得以门禁清单替代用户要求"。
5. **熔断**：连续 3 个同形态失败即停并诊断。

## 被否决的方案
| 方案 | 否决理由 |
|---|---|
| **进程退出码判成功** | **实测证伪**：`pi` 在内部模型调用 401 时**仍然 exit 0** → 前轮据此得出的"U18 已质变为真实引擎执行"**被撤回** |
| **判据由执行者自定** | 2.0 的 U15 自定"截图≥13 张" → 被 13 张同构截图钻空 |
| **capability-gap 登记制替代拦截** | 登记 ≠ 合规 → 改 U19 阻断 |
| **纸面"维度覆盖表"当质量对标** | "表格形态上覆盖了维度，视觉上像对标" |
| **用 md 报告/CLI 产物冒充 UI 验证** | 016 明确：standalone 页面、CLI 产物、骨架页均不构成 U15 证据；且禁止转 headless 冒充 UI 验证 |
| **本地确定性 JS 冒充引擎执行** | 2.0 实测 121 次 `workflow.skill` 全本地、`engine.run` 0 次 |

## 后果（本项目因此抓到的三类"假通过/假失败"）
1. **进程退出码** 假通过（U18）；
2. **CSV 解析空转** 假通过（表头核对 + PII 探测，见 ADR-0007）；
3. **stem 与带扩展名比对** 导致 33 条**假失败**；另有正则子串误判（`spend_wan` 含 "end"、`dept_quarter_pkg_wan` 含 "quarter"）注入日期 → **应用正确地拒绝了它们**（是应用正确，不是 bug）。
4. 落成纪律红线：「**凡'通过'都要问一句 —— 它是真的在检查，还是在空转**」。
5. 另有一处**反向误判**：1.0 的 `GT-TRN-01 机械判 FAIL`（实际落盘 35KB 有效产物）→ "判定系统双向都不可靠"。
