# ADR-0014 · 引擎整合：真实模型执行 + 降级必须标注（否决本地 JS 冒充）

- **状态**：已采纳（as-built，U18 第三轮重判 PASS）｜**决策日**：2026-09-27（U18 设立）→ 09-29 判据升级｜**模块**：M11
- **证据**：`015` L911/L972；`docs/why-not-met-2.0.md` L15/L215/L297；`reports/u18-engine-integration.md`；`reports/credential-unblock-3.0.md` §36-51

## 背景
2.0 的实测结论触目：**`workflow.skill` 执行 121 次全部是本地实现，`engine.run` 0 次**——"引擎整合"在业务流里**从未发生**。根因写在其代码注释里：`skill-runtime.mjs` 自陈"**确定性实现，不依赖模型输出，任何环境可复现**"。

## 决策
1. skill 节点的执行主体必须是 **pi / dsh 的真实模型调用**；
2. `engine.run` 审计数 **≥ GT 数**（U18 判据）；
3. 本地 JS 只可作为**断网降级**路径，且审计必须标 `fallback=offline`；
4. **降级率 > 50% = U18 FAIL**；
5. 执行链 `dsh exec → pi --mode json → fallback`，其中 `dsh exec` 需 headless `exec` profile（016 §6 集成点）；
6. **判据模型级**：`stopReason=stop` 且 `usage.totalTokens>0` 且正文非空。

## 被否决的方案
| 方案 | 否决理由 |
|---|---|
| **本地确定性 JS 冒充引擎执行** | 2.0 实证：121/121 本地、0 引擎；且这是 §14.6 的"本地 JS 执行=引擎整合"语义替换 |
| **用 `engine=pi, fallback=false` 判成功** | **实测证伪**：pi 在内部模型 401 时**仍 exit 0** → 该判据什么都证明不了 |
| **用进程退出码判成功** | 同上，已被明确禁止 |
| **dsh 侧失败就整条链判 FAIL** | `dsh exec` 曾报 `profile "exec" does not exist`；建 profile 后实跑通过（含 skill 节点装载 `SKILL-band-analysis.md`）→ 是环境缺配置，不是设计缺陷 |

## 后果与更正
- **更正（本项目最典型的一次"自我推翻"）**：前轮据 `engine=pi, fallback=false` 宣告"U18 已质变为真实引擎执行" → **主动撤回**，理由是该判据为伪；升级为模型级判据后**重新取证**，U18 才在第三轮重判 PASS（工作台内 `workflow-run` 审计 `tokens=65004 ok=true`；GT 侧累计 `engine.run(ok) 62` 条、**3,724,341 tokens**）。
- 工作台内 `engineRun()` 保留三级链（dsh → dsh-npx → pi → 本地 fallback），**dsh 分支的失败原因（需 exec profile）不是 bug，不得删除**。
- **遗留**：U17 对标仍不成立（基准仅 1/3、工作台臂 5/10、判分器 3 缺陷；可比值上工作台 3.65 < pi 4.45）——**这是当前 U19 阻断的主要来源之一**。
