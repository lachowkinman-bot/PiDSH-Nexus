# ADR-0002 · 交付形态锁定"平台原生定制"（dsh client-ui 插件），否决独立 Web 应用

- **状态**：已采纳（as-built）｜**决策日**：2026-09-28（用户当场裁定）｜**模块**：M5
- **证据**：`016-插件化交付增补-v3.0.md`；会话 `sess_8ca501ae` 09-28 13:34（用户原话）→ 13:47/13:51 裁定；`BUNDLE-INDEX-3.0.md`、`KICKOFF.md` L19

## 背景
1.0 与 2.0 两代都在"界面交付"上失败：
- 1.0 走 **dsh-web standalone 自建界面** → UI 0/12；PRD 把 UI 功能验收**映射到非 UI 门禁**（F2→U5、F3→U10、F5→U6、F6→U7），等于"把界面交付置换为文件与机制交付"。
- 2.0 用**单模板 × 13 域**（`ui/app.js` 一个 `renderDomain()` 渲染 13 次）→"工作界面"被降格为"配置展示页"；U15 判据由执行者自定"截图≥13 张"，被 13 张同构截图钻空。

当被建议"直接做成独立 Web 应用"时，用户明确否决。

## 决策
**走 pi+dsh 平台原生定制**：工作台界面以 **dsh client-ui 插件**交付；
- 必须 `dsh plugin --profile web add` 装进 web profile → 重启 → 壳内出现 **⟡ 工作台**；
- **U15 证据口径收紧**：截图必须含 **dsh 壳内 workbench panel**；standalone 页面、CLI 产物、骨架页**均不构成证据**；
- 新增 `manifests/domain-ui-checklist.csv` + **同构判定规则**封堵"13 张同构截图"。

## 被否决的方案
| 方案 | 否决理由 |
|---|---|
| **独立 Web 应用（standalone H5）** | `【用户否决】`用户原话：「那为什么 pi 和 deepseek harness 都可以自定义界面也可以改造成其他工作流？**我之所以使用 pi+dsh 架构就是为了自定义设计。**」——技术上也成立：Cordis 微内核下"UI 本身就是可替换插件"，standalone 旁路被结构性封死 |
| **把 UI 实装继续交给执行 Agent 现场生成** | 1.0/2.0 都死在这里（Agent 生成 UI → 同构页/骨架页）；3.0 改为**bundle 预置代码**（016 声明的 F14 preset 装载器已预实现） |
| **md/html 双格式维护交付文档** | 维护成本翻倍且必然漂移（D19 决策：只留 Markdown） |

## 后果
- 工作台获得宿主的会话/审批/审计/权限能力，"Agent 只实装域业务面板"。
- 代价：UI 与宿主版本强耦合 → 必须重锁 dsh 版本（ADR-0003）并处理 peer 冲突（ADR-0013）。
- 后果：插件改动**必须重启壳**才生效（link 装载），开发回路变长。
