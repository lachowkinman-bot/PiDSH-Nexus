# ADR-0010 · U19 交付阻断 + 宣告一致性（否决"未跑即宣告"）

- **状态**：已采纳（as-built，**至今仍生效**）｜**决策日**：2026-09-27（v2.2，L912/L917）｜**模块**：M10/M15
- **证据**：`015` L912/L917、`KICKOFF.md` L9；`docs/delivery-announcement-checklist.md`；`docs/why-not-met-2.0.md` L97/L280

## 背景
1.0 出现"门禁未跑完就宣称交付"；2.0 更严重——**内部报告写 1/24 已安装，对外宣告却写"181 个 tarball SHA256 全部复核通过…52 份域 SKILL.md 实际装载执行"**：内部诚实（报告）与外部表述（宣告）之间出现**语义升级**。

## 决策
1. **U19 阻断**：U3/U10/U15/U16/U17 任一 `NOT_RUN / PARTIAL / FAIL` → **禁止交付宣告，只输出阶段报告**。
2. **宣告用语与证据逐字一致**：`docs/delivery-announcement-checklist.md` 逐句对证据路径，无路径按 0 分。
3. **22 类缺陷清零表 + V1-V8 一票否决 + 每项评分必须引用证据路径**。
4. **诚实边界**（§13）：未核验的 Runner/形态/能力一律"矩阵照发、实测回填"，**不写能力承诺**。

## 被否决的方案
| 方案 | 否决理由 |
|---|---|
| **"未跑即宣告"**（1.0/2.0 的失败模式） | 直接触发阻断规则；用户对 1.0/2.0 的验收失败即由此而来 |
| **内部报告与对外宣告"两套口径"** | 2.0 实证：报告 1/24 vs 宣告"复核通过"——语义升级 |
| **用 capability-gap 登记替代拦截** | 登记 ≠ 通过 |
| **把 10 Runner 说成"全部支持"** | 9/10 未实测、2 个不可核验 → 明确"不得宣称 10/10 支持" |
| **把"文档质量 98 分目标"混作"交付线 85 分"** | 两个口径不得混用 |

## 后果
- 本项目**六轮从未宣告交付**：R6 结束时仍是"只出阶段报告"（U3/U16/U17 未 PASS）。
- 副作用（正面）：即使桌面版已真实跑通（双击启动、25/25 包、41/41 自检），也**不因此宣告达标**——因为 U17 对标未成立、U3/U16 的 L4 逐包循环未闭合。
- 该规则也约束本文档：`RETRO-PRD.md` 与各 ADR 均按"已达成/未达标/未验证"三态逐条标注，不写"全部完成"。
