# ADR-0006 · 工作台 UI 改为独立单页应用 + 单文件离线 HTML（八项决策 D1-D8）

- **状态**：已采纳（as-built，P0-P5 全部落地）｜**决策日**：2026-09-29（用户逐题确认）｜**模块**：M6
- **证据**：`docs/workbench-app-design-v2.md`（设计树 D1-D8，含用户原话）；会话 `sess_630e78a2` 15:54 → 16:01/16:06；`reports/app-smoke.json`、`reports/app-verification.json`

## 背景
用户实测壳内面板后给出四条症状：**「每一个工作域都不能成为独立的工作台界面；每一个模块的 UI 点开都是不能用；每一层都是重叠在一起的；整个面板也是挤在一起的」**。
代码级定位（先定位，不改症状）：面板是 dsh 壳 `main` 槽的**平级面板**，域详情只是该面板内的一个 view 分支（`client.js:399-401`），天生与对话区共享主区；面板根样式**无 `background`** 叠在主区上导致文字重叠；全局 13px 字号 + 10px 间距把 13 域硬塞一屏；"独有交互"是**内联表单**走 `io.submit()`，**多数无后端落点、无校验、无持久化**。

**结论：这不是样式微调问题，是形态问题**——面板形态无法承载 13 个独立工作台。

## 决策（八项，均经用户逐题确认）
| # | 决策点 | 选定 |
|---|---|---|
| D1 | 产品形态 | **独立单页应用**（回 PRD §1.3 原定形态） |
| D2 | 交付形态 | **单文件离线 HTML**（`file://` 不能 fetch 本地 JSON/CSV，故"双击即用"必须内联数据；≤1.5MB） |
| D3 | 域内粒度 | **每表/每流程单独成页**（≈150 页 → 实测 140 页） |
| D4 | 真相源 | 新增 `manifests/domain-model/<域>.json`（见 ADR-0007） |
| D5 | 导航骨架 | **两级侧边栏 + 驾驶舱**（保留用户认可的侧边栏形式） |
| D6 | 交互深度 | **真实读写 + localStorage 持久化**（用户目标即"所有 action 都能响应"） |
| D7 | 壳内面板 | **降为入口**（不改其 U15/U16 证据面） |
| D8 | 视觉与验收 | 舒适演示风 + 密度开关；**生成式全量冒烟**（非截图计数） |

## 被否决的方案
| 方案 | 否决理由 |
|---|---|
| **继续用壳内面板承载 13 域** | `【用户否决】`面板形态与对话区共享主区，无法让每个域成为独立界面；且层叠/拥挤是结构性的 |
| **多文件前端（外链 JS/JSON/CSV）** | `file://` 下不能 fetch 本地资源，"双击即用"不成立 |
| **只读展示** | 与用户目标（所有 action 可响应）直接冲突 |
| **按截图数量验收** | 2.0 已被 13 张同构截图钻空 → 改为"路由 + 动作清单逐条点击 + 四类断言" |
| **面板直接打开文件系统里的 app.html** | http 页不能跳 `file://`（浏览器普遍禁止）→ 改为**插件同源托管** `/workbench/api/app-page` |
| **删掉壳内面板** | 会毁掉 U15/U16 已验收的证据面 → 改"降为入口"并保留"面板内简版" |

## 后果
- 应用规模：**140 页**（驾驶舱 1 + 域概览 13 + 台账 33 + 流程 78 + 设置 13 + 2）；冒烟 **551/551 PASS / 0 JS 错误**；自检 **41/41**。
- 未决风险：体量（400-700KB，上限 1.5MB）；`file://` 下多副本共享同一 localStorage 域（缓解：键带构建指纹 / 导出 JSON 作权威备份）；"员工自助端"是否作第 14 入口未决。
- 真实执行中修掉的 5 个"尺子 bug"（全在脚本/模型侧，非应用缺陷）：`pages[].table` 带扩展名、流程 stem 取法对 `a.b@1.0.0` 得 `"0"`、状态跨轮次不清、两实例并发、取值器先判日期后判数值——均记入 r5 交接。
