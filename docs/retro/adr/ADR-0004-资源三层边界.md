# ADR-0004 · 资源三层边界 + "清单唯一真源"（否决"字面所有包现成"）

- **状态**：已采纳（as-built）｜**决策日**：2026-09-27 10:22 / 10:46；09-28 扩清单｜**模块**：M1
- **证据**：`015` §3（L122-130、L925）、§3.6；`reports/catalog-fake-packages.md`；`reports/disabled-packages.md`；会话 `sess_8ca501ae`(10:22/10:46)、`sess_babee05a`(18:41 用户)

## 背景
用户要求"任务书必须已包含现成全部资源（packages/skills/plugins/extensions/依赖/preset 文档/PRD/CR/README），发给任一 Agent 即可"。但行业 MCP/ERP/HRIS 连接器在企业侧**不存在统一现成包**；且曾出现"21/22 个行业包名虚构"的事故。

## 决策
**三层资源边界**：
1. **预置层**：核心 P0/P1 tarball + 便携 Node 运行时 → **零下载**；
2. **自制层**：13 域 preset 设计文档、PRD、CR checklist、双 README → **零生成**，Agent 只做定制；
3. **缺口层**：扩展位 + `capability-gap.md` 登记，**明示"无现成包"**并给降级路径（自建 MCP / 人工导出 / 暂缓）。

配套：`manifests/*.csv` 为**唯一真源**（文档禁止复制包表格）；新增任何包名**必须先 `npm view` 核实**，找不到即登记缺口（编造包名 = V6 一票否决）。

## 被否决的方案
| 方案 | 否决理由 |
|---|---|
| **"字面所有包都现成预置"** | 物理上不存在；强行声称会重演"虚构包名"事故。改用"P0/P1 零下载 + P2 模板零生成 + 已知缺口 gap 化" |
| **只筛 24 个精选包** | `【用户否决】`用户原话：「5000 多个 pi packages 和 10000 多个 dsh-plugin **只筛选出 24 个？？不够全面**，我还要更全面的」→ 扩到 **1006 条**（pi 602 / DSH 404），并保留"启用/备选"分层 |
| **第三方插件市场站作来源** | 多为无背书 SEO 群站——"**indexed ≠ verified**" |
| **引用 28 个不存在的包** | `pi-mentis-memory` npm 404、`pi-archive` 归属错、`composio-x-pi` 非官方 → 建档 `catalog-fake-packages.md`，禁引用 |
| **把"哈希校验"当"安装完成"** | 1.0 的 `catalog_verified=155/155` 只是哈希通过 → 语义漂移，见 ADR-0009 |

## 后果
- 交付包自带 179 tarball，可在无网环境完成 P0/P1 安装（**但传递依赖仍需 registry/热缓存**，见 `desktop-acceptance.md` §6.1 的未达标登记）。
- 清单必须"期前刷新"（数字过时快：awesome-dsh-plugin 3014→3196 等）。
