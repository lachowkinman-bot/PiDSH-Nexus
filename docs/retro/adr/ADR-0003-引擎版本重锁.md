# ADR-0003 · 引擎版本重锁 dsh 0.1.7-rc.2（否决沿用 0.1.5-rc.3 / 跟随 latest）

- **状态**：已采纳（as-built）｜**决策日**：2026-09-28 13:47-13:51，2026-09-29 复跑确认｜**模块**：M1/M5/M14
- **证据**：`016-插件化交付增补-v3.0.md` §2；`tools-versions.txt`；`reports/u1-bundle-audit.md`；`reports/catalog-install-failures.md` L5；`progress.md` L31

## 背景
1.0 锁定 dsh `0.1.5-rc.3`。切到插件化路线后，范本插件（`@linxin666/dsh-client-ui-task-board@0.4.3`）在 `dsh.engines.dsh` 中声明 **`>=0.1.7-rc.2`**，且 client-ui 的 `client.inject/slots` 契约需要该版本；同时 CVE-2026-82533（CVSS 9.4 沙箱逃逸，影响 ≤0.1.1-rc.2）要求底线 ≥0.1.2。

## 决策
**重锁 `@deepseek-ai/dsh@0.1.7-rc.2`**（SHA256 `5f2da7272d9485abc223e681075809a8d929697c5232ee445718e1b7e066bff8`）：
- 引擎**只从离线 tarball 安装**，安装后断言 ≥0.1.2，**禁止 registry 降级**；
- manifest 引擎行回写 0.1.7-rc.2，U1 复跑 PASS；
- profile 侧以 `overrides` 钉同版本（见 ADR-0013）。

## 被否决的方案
| 方案 | 否决理由 |
|---|---|
| 沿用 `0.1.5-rc.3` | 低于插件契约要求（`>=0.1.7-rc.2`），插件装载即失败 |
| 跟随 `@latest` / `0.2.0-rc.x` | 项目**禁用 latest 政策**；且 catalog 包 peer 声明 0.2.0-rc.1 曾把整套 0.2.0-rc.1 拖进 profile → 与 0.1.7-rc.2 冲突 → **91 行禁用 + dsh-llm-pi-ai 崩溃整壳** |
| 按 catalog 清单行装 `0.1.5-rc.3` | 实测被 **SKIP（引擎版本锁）**："引擎已装 0.1.7-rc.2（更高且为锁定版本），禁降装" |
| 用 `@anionex/dsh-vision-toolkit`（面向 0.2.0-rc.x API） | 装后激活失败 `ctx.settings.register is not a function` → **不兼容-停用**，待 0.2.x 重评 |

## 后果
- 与引擎内建同名的 catalog 包必须移出 profile（11 个），并留台账 `reports/disabled-packages.md`。
- 每次引擎升级都要重评该台账与豁免清单（遗留项）。
- **更正记录**：本决策本身就是对"沿用 0.1.5-rc.3"的更正；manifest 曾与 016 冲突，已回写并复跑 U1。
