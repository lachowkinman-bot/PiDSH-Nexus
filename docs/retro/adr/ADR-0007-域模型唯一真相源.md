# ADR-0007 · 域模型为唯一真相源 + 构建期硬校验（否决三处真相源）

- **状态**：已采纳（as-built）｜**决策日**：2026-09-29｜**模块**：M7/M8/M9
- **证据**：`docs/workbench-app-design-v2.md` D4/D8；`scripts/gen-domain-model.mjs`、`scripts/build-app.mjs`；`reports/domain-model-validation.md`（0 违规 / 0 警告）；r5 交接 §4 第 3 条

## 背景
应用要生成 140 页、33 张表页、78 条流程页，且每页的列/状态机/审批链/校验规则必须与数据、场景、文档一致。此前真相源有**三处**（`manifests/scenes` / CSV 数据 / `docs/preset-design` 文档），并且**已经漂移过**。

## 决策
`manifests/domain-model/<域>.json`（13 个）为**唯一机器可读真相源**，声明：表/字段/行数/工作流节点链/状态机/审批链/校验规则/页面清单。
数据流：`CSV（真值） + scenes/workflows（流程与技能） → domain-model.json → app.html + docs/preset-design/*.md + smoke-plan`。
**任一处漂移，构建即失败**：
- `gen-domain-model.mjs --check`：CSV 表头逐字一致 / 技能覆盖 / 工作流技能 ∈ 声明 / GT 绑定 / PII 未脱敏探测；
- `build-app.mjs`：`--check` 通过 + `app.js` 语法 + 表头一致 → 才产出 `app.html`。

## 被否决的方案
| 方案 | 否决理由 |
|---|---|
| **沿用三处真相源 + 人工核对** | 已漂移过；140 页规模下人工核对不可持续 |
| **让 Agent 现场生成页面** | 1.0/2.0 的失败模式（同构页/骨架页）→ 改为预置生成器 + 构建期门禁 |
| **验收靠"页面能打开"** | 渲染≠界面交付（§14.6）→ 改为生成式冒烟（路由 + 动作 + 四类断言） |
| **只检查"文件存在/行数"** | 文件计数≠能力可用（§14.6） |

## 后果
- 构建即门禁；`reports/domain-model-validation.md` 常驻 0 违规 / 0 警告。
- **⚠️ 假通过事件（本项目最重要的教训之一）**：早期版本误用 markdown 的 `|` 切分去解析 CSV → 模型的 `columns` **恒为 1 个元素** → "表头逐字核对"与"PII 未脱敏探测"**双双空转（假通过）**。修为标准 CSV 解析后列数恢复真实，PII 探测真的在工作（识别出 `applicant_masked`/`customer_masked`，确认无未明脱敏原值）——**结论没变，但现在是真的验过**。
- 由此产生纪律红线：「**凡'通过'都要问一句 —— 它是真的在检查，还是在空转**」。
