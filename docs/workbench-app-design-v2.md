# 工作台界面重构设计 v2（独立单页应用）

> 日期：2026-09-29 ｜ 起因：用户实测反馈——「侧边栏尚可，但点进工作域后，每个域不能成为独立工作台界面；每个模块 UI 点开不可用；各层重叠；整个面板挤在一起」
> 本文是经逐项确认的设计决策记录（八项决策均经用户逐题确认），不是提案。

## 0. 症状 → 代码根因（先定位，不改症状）

| 症状 | 代码根因 | 定位 |
|---|---|---|
| 工作域不能成为独立界面 | 工作台整体只是 dsh 壳 `main` 槽的**平级面板**，域详情是该面板内的一个 view 分支，天生与对话区共享主区 | `client.js:399-401`（`slots.register({name:"main", key:PANEL_ID})`） |
| 各层重叠 | 面板根样式**无 `background`**，叠在主区内容之上时透明，两层文字直接重叠 | `client.js:53`（已修，见 §7.1） |
| 面板挤在一起 | 全局 `fontSize:13px` + `gap:10px`，13 域用 `minmax(300px,1fr)` 硬塞一屏 | `client.js:53,57` |
| 模块 UI 点开不能用 | 「独有交互」卡是内联表单，走 `io.submit(kind,payload)`，多数无后端落点、无校验、无持久化 | `client.js:84-170` |

**结论**：这四条不是样式微调问题，是**形态问题**——面板形态无法承载 13 个独立工作台。故本轮改为独立应用。

## 1. 八项已定决策（设计树逐项确认）

| # | 决策点 | 选定 | 关键理由 |
|---|---|---|---|
| D1 | 产品形态 | **独立单页应用** | 回 PRD §1.3 原定形态；壳内面板形态无法让每个域成为独立界面 |
| D2 | 交付形态 | **单文件离线 HTML** | `file://` 下不能 fetch 本地 JSON/CSV，故"双击即用"必须内联数据；符合 PRD §1.3/§4.1（≤1.5MB，无网络依赖） |
| D3 | 域内粒度 | **每表/每流程单独成页**（≈150 页） | 最贴 PRD「模块→子页」口径；一屏只装一件事，根治"挤" |
| D4 | 真相源 | **新增 `manifests/domain-model/<域>.json`** | 现状三处（scenes / CSV / preset-design 文档）已漂移过；单一机器可读源，app 与文档同源生成并与 CSV 表头硬校对 |
| D5 | 导航骨架 | **两级侧边栏 + 驾驶舱** | 保留用户认可的侧边栏形式，升级为两级；驾驶舱做跨域 KPI 与待办审批聚合 |
| D6 | 交互深度 | **真实读写 + localStorage 持久化** | 用户上一轮目标即"所有 action 都能响应"；只读展示做不到 |
| D7 | 壳内面板 | **降为入口**（不改其 U15/U16 证据面） | 面板保留用于 U15/U16 验收；"进入域工作台"改为打开 `app.html#/<域>` |
| D8 | 视觉与验收 | **舒适演示风 + 密度开关**；**生成式全量冒烟** | 直接治"挤"；150 页 × 多动作只能靠生成式冒烟才敢声称"全量可响应" |

## 2. 目标架构

```
universal-workbench-3.0/
├── manifests/domain-model/          ← 新增：唯一真相源（13 个 JSON）
│   └── <domain>.json                  表/字段/状态机/审批链/校验/页面清单
├── src/                             ← 新增：应用源码（人类可读、可 diff）
│   ├── app.js                        路由 + 布局 + 状态（localStorage）
│   ├── components/                   表格/抽屉/步骤条/表单/卡片/面包屑
│   └── theme.css                     设计令牌（间距/字号/圆角/主题色）
├── scripts/
│   ├── gen-domain-model.mjs         ← 从现有资产生成 domain-model（一次性迁移）
│   ├── build-app.mjs                ← domain-model + CSV → app.html（单文件内联）
│   └── smoke-app.mjs                ← 生成式全量冒烟（D8）
├── app.html                         ← 构建产物（双击即用，交付物）
└── templates/workspace/data/**      ← 数据源，不改
```

数据流：`CSV（真值） + scenes/workflows（流程与技能） → domain-model.json → app.html + docs/preset-design/*.md + smoke-plan`。
**任一处漂移，构建即失败**（CSV 表头与字段字典不一致直接报错）。

页面总数：1（驾驶舱）+ 13（域概览）+ 33（台账）+ 78（流程）+ 13（设置）+ 2 = **140 页**。

## 4. 页面模板（四类，全部由 domain-model 驱动）

| 模板 | 内容 | 动作（可点且真实生效） |
|---|---|---|
| **域概览** | 域 KPI 卡、状态机图（枚举+迁移）、审批链图（节点-角色-双审批-阈值）、本域 GT 三条 | 跳转台账/流程；一键域冒烟 |
| **台账页**（每表） | 工具条（搜索/筛选/分页/列显隐）+ 全宽表格（表头 sticky）+ 行点击开右侧抽屉（详情/编辑/删除） | 新增/编辑/删除/导出 CSV；字段校验按 §9 规则 |
| **流程页**（每流程） | 步骤条（已完成✓/当前/待办）+ 审批区（通过/驳回，驳回必填原因）+ 交付规范（文件/字段/验收标准）+ 回滚点 | 发起/推进/驳回/取消；每次动作写审计并落 localStorage |
| **域设置** | 最低级别、双审批、脱敏字段、记忆层策略、GT 冒烟入口、域数据重置 | 重置本域/导出本域 JSON |

## 5. 交互与持久化规范（D6）

- 存储：`localStorage`，键前缀 `hr_workbench_`（PRD §4.3）：`hr_workbench_data_<域>`、`hr_workbench_audit`、`hr_workbench_ui`（主题/密度/展开态）。
- 首次打开：以 `app.html` 内联的种子数据初始化；此后以 localStorage 为准。
- **每次动作三重效果**：① 状态变更（状态机按 domain-model 迁移）② 审计追加一条（动作/对象/前后值/时间）③ 持久化。
- **校验前置**：字段级校验（必填/唯一/格式/阈值）不通过则在字段下红字提示，不产生半成品记录。
- 一键能力：重置本域 / 重置全部 / 导出 JSON / 导出 CSV。
- 权限门控（PRD §2.2、K2）：顶部角色切换（admin/hr/employee）；**无权限的按钮不渲染**（非置灰），employee 仅见本人在数据行（数据边界）。

## 6. 视觉规范（D8）

```
--space-1..6 : 4 / 8 / 12 / 16 / 24 / 32px      8px 刻度
--font-base  : 15px（紧凑模式 13px）  行高 1.6
--content-max: 1440px 居中
--drawer-w   : 420px      --table-row: 44px
--radius     : 10px       --theme: ocean | emerald | violet
```
顶栏（面包屑 + 域名 + 操作）与表头 sticky；卡片最小宽 320px、一屏最多两栏；密度开关与主题色共用同一套 CSS 变量。

## 7. 验收（D8：生成式全量冒烟）

1. **构建期静态校验**：domain-model ↔ CSV 表头逐字段核对；每域 3 技能/6 流程/3 GT 齐备；路由无重复无孤儿。不符即构建失败。
2. **生成式冒烟** `scripts/smoke-app.mjs`：从 domain-model 生成「路由 + 动作」清单 → 无头浏览器逐路由访问、逐动作点击 → 每页四类断言：
   - 状态真的变了（前后快照 diff）｜审计新增一条｜非法输入被拦下｜无权限时不渲染。
   产出 `reports/app-smoke.csv`（逐页 PASS/FAIL）与失败页截图。
3. 只有第 2 步全绿，才可声明"所有 action 可响应"；否则按页登记 FAIL。

## 9. 本次已当场修掉的症状

`client.js:53` 面板根样式补 `background:#fff; position:relative; zIndex:1; isolation:isolate`——消除"各层重叠"。
（面板仍在，属 P5 之前的即时缓解；域详情迁出属 P1-P3。）

## 10. 风险与未决

- **体量**：140 页 + 33 表 + 78 流程内联进单文件，预估 400-700KB（PRD 上限 1.5MB）。若超限，退路是把 13 域文档（非运行时内容）排除、仅内联运行必需数据。
- **localStorage 在 `file://` 下**：Chrome/Edge/Firefox 均可用，但同一浏览器下所有 `file://` 页面共享一个存储域，多份副本会互相覆盖。**缓解**：存储键带构建指纹，或提供"导出/导入 JSON"作为权威备份。
- **未决**：是否把 PRD 的"员工自助端"作为第 14 个入口（当前 13 域已含 employee 角色数据边界，但无独立自助导航）。
# v4 增补：战略驱动与运行闭环（2026-09-30）

`app.html` 保留为辅助的 13 域台账视图；完整业务操作以 DSH 壳内 `⟡ 工作台` 为唯一权威工作面。

## 页面结构

- 战略总看板：Objective → 5 个 KR → 13 域北极星 → 工作流证据 → 实际/偏差/阻塞。
- 13 域工作台：每域独立经营路径、业务脉搏、6 条流程、数据台账、交付物、运行记录。
- 工作流向导：输入、规则校验、LLM 结构化分析、质量门、角色签名审批、发布、成效、战略回写。
- 审批中心、交付物、审计与备份、运行与回退。

## 数据与安全

- 用户数据在 `%LOCALAPPDATA%\PiDSH Nexus\workspace`，模板只读。
- 每次写动作前创建快照备份，最多保留 30 份。
- LLM 输出必须是结构化 JSON，带证据引用、置信度和脱敏记录；失败保持 `blocked_model`，不得生成正式终态。
- 双审批必须使用不同角色和不同操作者签名。

## 兼容

- 旧 `/workbench/api/scenes|apply|save|workflow-run|deliver...` 继续保留。
- 新平台端点使用 `/strategy/overview`、`/workflow-definitions`、`/workflow-instances*`、`/imports`、`/metrics`、`/backups`。
